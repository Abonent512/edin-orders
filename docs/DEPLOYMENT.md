## Как показать кейс

1. В веб-клиенте войдите кнопкой «Покупатель», соберите корзину и оформите заказ с синтетическими данными.
2. На телефоне откройте `/mobile/` и также выберите «Покупатель». Заказ доступен с тем же номером, суммой и статусом.
3. Оператора откройте в отдельном браузере или приватном окне, выберите «Оператор» и измените статус. Покупатели получат обновление автоматически.
4. Для Android установите APK и на его стартовом экране укажите `https://edin-orders-abonent512.onrender.com`, затем войдите в тот же аккаунт. На физическом устройстве APK ещё требует проверки владельцем.

Сейчас включён `DEMO_MODE=true`: демонстрационные роли доступны без пароля, товары/условия учебные, оплата при получении. Для реальных пользователей выключите деморежим и создайте оператора через CLI по инструкции эксплуатации.

## Что развёрнуто

- Render: сервис `edin-orders-abonent512`, тариф **Free**, регион Frankfurt.
- Neon: отдельный проект `edin-orders`, тариф организации **Free**, PostgreSQL 17, AWS Frankfurt, вычислительный размер 0.25 CU.
- Данные находятся в Neon и не используют непостоянный диск Render.
- Backend использует прямой адрес PostgreSQL; адрес с `-pooler` несовместим с заданными startup-таймаутами. Приложение самостоятельно держит ограниченный пул до 5 соединений.
- `DATABASE_URL` и `JWT_SECRET` хранятся в настройках Render; их значения не включены в репозиторий или архив.
- Стандартный origin Render определяется автоматически, JWT остаётся в памяти клиента, refresh cookie — HttpOnly/Secure.
- Обновления `main` запускают автоматическое развёртывание. Документация и архив в `releases/` позволяют воспроизвести проект локально.

## Проверки опубликованного API

Проверены успешное создание заказа и расчёт цены сервером, одинаковый заказ в независимых web/mobile сессиях, идемпотентный повтор, запрет смены статуса покупателю (403), требование входа (401), чужой заказ (404), неправильный телефон (422), конфликт версии (409), живой SSE и согласованные статусы. Тестовый заказ отменён, его остатки возвращены.

Все страницы, OpenAPI, манифест и APK отвечают по HTTPS. Полученный APK совпадает с подписанным файлом в репозитории по SHA-256. Локальный браузерный сценарий Chromium пройден; внешний браузерный прогон в облачной QA-среде ограничен отсутствием доверия Chromium к сертификату сетевого прокси. Проверки опубликованного HTTPS API и SSE выполнялись с проверкой сертификатов.

Итоговый протокол выпуска: https://github.com/Abonent512/edin-orders/releases/tag/v1.0.0

## Бесплатные лимиты

Render Free засыпает после 15 минут без входящих запросов; первое открытие после сна может занять около минуты. Neon Free имеет лимиты вычислений, хранения и трафика. На момент публикации: 100 CU-часов в месяц и 1 ГБ Postgres-хранилища на проект; превышение квот может приостановить работу до сброса лимита. Доступность из всех российских сетей и SLA бесплатные зарубежные тарифы не гарантируют. Инструкция переноса на российский VPS: `OPERATIONS.md`.
