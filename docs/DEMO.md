# Демонстрация кейса: 3–5 минут

## Подготовка

Локально: запустить `scripts/start-demo.sh` / `scripts/start-demo.ps1`. В облаке: успешный Render deployment, `DEMO_MODE=true`, постоянная PostgreSQL. Везде используйте синтетические данные.

Окно A — покупатель, веб-клиент `/`. Окно B — тот же покупатель, `/mobile/` или Android APK. Окно C — оператор в **отдельном браузере/приватном профиле**, чтобы роли не делили refresh cookie.

## Сценарий

1. В A выбрать «Покупатель». Найти дрель через поиск, добавить её в корзину. В корзине изменить количество, проверить пересчёт.
2. Указать «Тестовый покупатель», номер `+79000000000`, выбрать самовывоз. Подтвердить передачу данных для обработки заказа. Отправить заказ.
3. Открыть карточку заказа. Зафиксировать номер, позиции, сумму, статус «Новый». Оплата — при получении.
4. В B войти под тем же покупателем. В списке есть **тот же номер и id**, та же сумма, позиции и статус.
5. В C войти как «Оператор». Открыть заказ и перевести его в «Подтверждён», затем «Собирается».
6. Показать A и B: без ручного обновления появляется новый статус и записи истории. Обычно задержка до 1–2 секунд; при буферизации SSE резервный polling до 30 секунд.
7. Перезагрузить A/B: заказ остаётся. Перезапустить backend/Render: после восстановления соединения заказ сохраняется, поскольку находится в постоянной БД.
8. В C провести заказ до «В пути» → «Получен». Показать полную историю.

## Проверки ошибок

- Некорректный телефон или пустое имя: браузер и сервер отклоняют заказ, сервер возвращает 422.
- HTTP PATCH статуса с JWT покупателя: 403 независимо от интерфейса.
- Войти другим обычным аккаунтом: чужой заказ не виден, прямой GET его id даёт 404.
- Повторить POST с тем же `Idempotency-Key` и телом: 200 и прежний заказ, а не дубль.
- Оператор посылает устаревшую `version`: 409, клиент обновляет данные.
- Отключить интернет после загрузки: появляется понятная плашка, приложение не падает, корзина остаётся на устройстве. Оформление без сети недоступно.

Эти свойства покрываются автоматическими API-тестами и сценарием `scripts/integration.py`; визуальная демонстрация выполняется в браузере/на устройстве после запуска.
