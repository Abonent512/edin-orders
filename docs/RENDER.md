# Бесплатный Render: публикация отдельного проекта

Это отдельный проект; чужой сервис `zapis-service.onrender.com` не изменяется.

## 1. Постоянная база

Создайте PostgreSQL в собственном аккаунте Neon либо другом провайдере с подходящим бесплатным тарифом. Перед созданием проверьте текущую стоимость и квоты в панели провайдера. Не выбирайте платные дополнения. Для Neon используйте прямую строку PostgreSQL с `sslmode=require` (Connection pooling выключен). Backend уже ограничивает собственный пул пятью соединениями; прямой endpoint поддерживает используемые параметры таймаутов подключения.

Скопируйте строку подключения в секрет `DATABASE_URL` **в панели Render**. Не публикуйте её в репозитории, скриншотах или чате. Выделите отдельную базу для проекта; не подключайте произвольную существующую базу с чужими таблицами. Пользователю приложения нужны права создавать таблицы при первом запуске и выполнять CRUD над ними.

Не создавайте Render Postgres Free для постоянного проекта: на момент проверки документации 07.11.2026 база действует только 30 дней. Источник: https://render.com/docs/free

## 2. Репозиторий

Создайте новый репозиторий GitHub и загрузите содержимое проекта из архива так, чтобы `Dockerfile`, `render.yaml`, `frontend` и `backend` находились в корне. Веб-сборку `frontend/dist` загружать необязательно: Docker собирает её сам. Не загружайте `.env`, `data`, `.venv`, `node_modules`, резервные копии и ключи Android.

## 3. Render

В Render: **New → Blueprint → выбрать репозиторий**. Проверьте план **Free**. Blueprint создаёт только один веб-сервис и не создаёт платных баз, дисков или фоновых сервисов.

Заполните:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string из шага 1, с TLS |
| `JWT_SECRET` | Генерируется Blueprint; не меняйте при обычном деплое |
| `ALLOWED_ORIGINS` | Необязательно: дополнительные домены через запятую. Стандартный адрес Render добавляется автоматически из `RENDER_EXTERNAL_URL` |
| `COOKIE_SECURE` | `true` |
| `DEMO_MODE` | `true` для защиты, `false` перед реальными пользователями |

Стандартный адрес `onrender.com` определяется при старте автоматически. Для собственного домена добавьте его в `ALLOWED_ORIGINS` без завершающего `/`; несколько адресов перечисляются через запятую. Сервер отклоняет изменяющие запросы с посторонних Origin. В `DATABASE_URL` и `JWT_SECRET` используются только секретные поля Render.

Дождитесь успешного health check `/api/v1/health`. Затем откройте корень, `/mobile/`, `/api/docs`. На телефоне в APK введите корневой HTTPS-адрес.

Приложение намеренно не запускает PostgreSQL без постоянного `JWT_SECRET` длиной от 32 символов. Локальную SQLite на Render не используйте. Blueprint требует вручную заполненный `DATABASE_URL`; если его оставили пустым, развёртывание нужно исправить до демонстрации. В Render код дополнительно проверяет наличие внешней БД.

## 4. Оператор без shell на Free

Для демонстрации достаточно `DEMO_MODE=true`: в интерфейсе есть демооператор. Для реальных данных отключите деморежим. Оператора создайте со своего компьютера через защищённое подключение к **той же базе**, используя секреты в локальных переменных окружения и команду:

```sh
PYTHONPATH=backend .venv/bin/python -m app.admin operator@example.ru --name 'Оператор'
```

Перед командой локально настройте `DATABASE_URL` и тот же `JWT_SECRET` через защищённый менеджер секретов/переменные окружения. Пароль вводится скрыто в интерактивном запросе. Его нет в аргументах командной строки. Не оставляйте секреты в истории shell.

## 5. Границы бесплатного варианта

- Render Free засыпает после 15 минут простоя, первый запрос может занять около минуты или дольше. Клиент показывает ошибку связи и позволяет безопасно повторить запрос.
- Заказы находятся во внешней PostgreSQL и не пропадают при рестарте Render. Сохраняйте `DATABASE_URL` и `JWT_SECRET` между публикациями.
- Квоты бесплатных вычислений, трафика, сборок и БД ограничены. При исчерпании квот сервис может стать недоступным до сброса лимита. SLA нет.
- Внешние бесплатные БД могут менять тарифы, правила простоя и резервирования. Не полагайтесь на бесплатный тариф как на единственную копию важных заказов.
- Не используются искусственные запросы для обхода режима сна хостинга.
- Render и Neon находятся вне РФ. Доступность из всех российских сетей и размещение персональных данных в РФ таким вариантом не обеспечиваются. Для реального сбора персональных данных граждан РФ вопрос первичного хранения и применимых требований нужно решить до запуска; проект переносится на российский сервер без переписывания клиентов.

Никакой Render-сервис не считается опубликованным, пока аккаунт не подключён, deployment не завершился успешно и не получен фактический URL. Исходники и Blueprint сами по себе не создают доступ к аккаунту.
