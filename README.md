# ЕДИН — омниканальная система заказов Web + Mobile

Решение кейса № 9 номинации «Программирование (разработка мобильных и веб-приложений)» форума «Умная индустрия».

Покупатель оформляет заказ на сайте или в Android-приложении, оператор переводит его по этапам, оба клиента получают единое состояние из общего API. В комплекте веб-клиент, мобильный интерфейс/PWA, исходники Android-клиента, FastAPI backend, SQLite/PostgreSQL, OpenAPI, тесты и Docker.

## Быстро посмотреть на компьютере

Нужен Python 3.12+. Для пересборки фронтенда нужен Node.js 22+. В архив включена готовая веб-сборка: повторно собирать её не требуется.

Windows PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-demo.ps1
```

Linux/macOS:

```sh
bash scripts/start-demo.sh
```

Открыть:

- Веб-клиент: http://localhost:8000/
- Мобильный клиент: http://localhost:8000/mobile/
- Интерактивный контракт API: http://localhost:8000/api/docs

В деморежиме на экране входа есть кнопки «Покупатель» и «Оператор». Оператору используйте отдельный браузер или приватное окно: cookie одного сайта общие для вкладок. Демоаккаунты и товары синтетические. Реальные персональные данные в демонстрацию не вводить.

Заказы сохраняются в `data/orders.sqlite3` и переживают перезапуск. Чтобы показать один заказ в двух каналах, откройте веб- и мобильный клиенты под одним покупателем; оператор — в отдельном браузерном профиле. Подробный сценарий: [docs/DEMO.md](docs/DEMO.md).

## Бесплатное размещение

Подготовлен `render.yaml`: один бесплатный Docker Web Service Render. Локальная SQLite **не подходит** для Render Free, поскольку файловая система непостоянная. Для облака укажите `DATABASE_URL` постоянной PostgreSQL, например проекта Neon с подходящим бесплатным тарифом. Бесплатную Render Postgres не используйте для долгого хранения: она истекает через 30 дней согласно документации Render, проверенной 07.11.2026.

Пошаговая публикация: [docs/RENDER.md](docs/RENDER.md). Потребуются аккаунты GitHub, Render и провайдера PostgreSQL. Они не создаются автоматически из исходников. Секреты вводятся в панели хостинга, не в код и не в переписку.

Бесплатные тарифы могут менять квоты и условия. Render Free засыпает после 15 минут без входящего трафика; первый запрос после сна медленный. Непрерывную работу 24/7 и доступность у всех российских провайдеров бесплатный зарубежный хостинг не гарантирует. Данные PostgreSQL сохраняются независимо от перезапуска веб-сервиса.

Для российской инфраструктуры есть автономный Docker-вариант: [docs/OPERATIONS.md](docs/OPERATIONS.md). Интерфейсы, шрифты, иллюстрации и Swagger локальные; внешний CDN и Google для работы клиентов не нужны.

## Android

Тонкий Android-клиент на Java/WebView, Android 8+; готовый APK находится в `releases/edin-android-demo.apk` и подключается к мобильному интерфейсу вашего HTTPS-сервера. Бизнес-логика и контроль доступа выполняются backend. Это не приложение на Flutter и не нативный офлайн-каталог.

После публикации APK можно скачать с `/downloads/edin-android-demo.apk` на том же сервере. На стартовом экране APK введите `https://<ваш-сервис>.onrender.com`, затем войдите с тем же email и паролем, что на сайте. До публикации сервера APK не показывает каталог. Пакет использует разрешение доступа к интернету, не запрашивает геолокацию и контакты, не обходит ошибки TLS и не хранит пароль в настройках.

Сборка исходников: `ANDROID_SDK_ROOT=/путь/к/sdk bash mobile/build.sh` (JDK 17, Android platform 35, build-tools 35.0.0). По умолчанию создаётся APK для демонстрации с тестовой подписью. Для постоянного распространения задайте `EDIN_KEYSTORE` и сохраните собственный ключ; не добавляйте его в Git. APK собран и проверен `apksigner`; проверка на физическом устройстве в этой среде не выполнена.

Дополнительно мобильный клиент устанавливается как PWA по HTTPS. Service worker кэширует статические файлы, не кэширует персональные API-ответы. Корзина хранится на устройстве; отправка заказа требует сети. Веб- и мобильная корзины самостоятельные, оформленные заказы общие.

## Проверки

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt
PYTHONPATH=backend .venv/bin/pytest backend/tests -q
cd frontend && npm ci && npm run build
```

PostgreSQL: задайте `TEST_POSTGRES_URL` адресом **только тестового** сервера с правом создания баз. Тесты создают и удаляют отдельную случайную базу на каждый случай, не используют `DATABASE_URL` разработчика. Для живой синхронизации и перезапуска: `.venv/bin/python scripts/integration.py`.

## Проверка интерфейса в браузере

Дополнительно можно прогнать реальное оформление и синхронизацию в Chromium. Установите опциональный `backend/requirements-browser.txt`, затем при необходимости `python -m playwright install chromium`. Запустите локальную демонстрацию и в другом терминале:

```sh
python scripts/browser_smoke.py --url http://127.0.0.1:8000 --output /tmp/edin-browser-qa
```

Тест запускается только при `DEMO_MODE=true`, использует синтетические данные, проверяет компьютер, телефон, оператора и вкладки с общей cookie; после проверки отменяет тестовый заказ, возвращая остаток. Если используется установленный системный Chromium, путь можно задать через `CHROMIUM_PATH`. В Windows укажите существующую папку для `--output`.

## Что входит

| Требование кейса | Реализация |
|---|---|
| Общий backend и версия API | FastAPI, `/api/v1`, OpenAPI 3.1 |
| Веб-клиент | Каталог, поиск/категории/сортировка, корзина, оформление, история |
| Мобильный клиент | Android APK + мобильный интерфейс/PWA `/mobile/` |
| Авторизация и роли | JWT 15 минут, HttpOnly refresh cookie, серверные проверки, покупатель/оператор |
| Единые заказы | Одна БД, собственные заказы для покупателя, все заказы для оператора |
| Синхронизация | SSE, переподключение с курсором, резервное обновление каждые 30 секунд |
| Ошибки | Структурированные журналы, request ID, единый формат ошибок и HTTP-коды |
| Автотесты | Права, изоляция пользователей, валидация, остатки, идемпотентность, конфликты, сессии |
| Развёртывание | Docker, Render Blueprint, вариант российского VPS |
